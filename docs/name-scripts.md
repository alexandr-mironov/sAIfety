# Имена в кириллице и латинице

«Шахержон Тахержон» — имя человека в кириллице. `Shaherzhon Taherzhon` и
`Shakherzhon Takherzhon` здесь рассматриваются как возможные латинские записи,
а не как единственная правильная транслитерация. `Ivan Petrov` — такой же случай
латинской записи имени. Для защиты нужно определять персональное имя и его
границы в данных, а не национальность человека.

## Что уже есть

Основной режим не изменён: правила русских ФИО и мобильных РФ, без модели.
Кириллица сама по себе не означает, что словарь/окончания распознают имя.
Латиница сама по себе также не является основанием для маскирования.

| Пример | Поле / контекст | Основной режим |
|---|---|---|
| `Иван Петров` | обычный текст | распознаётся правилами |
| `Шахержон Тахержон` | обычный текст | текущие правила пропускают |
| `Шахержон` / `Тахержон` | отдельные `first_name` / `last_name` | маскируются как кириллические компоненты записи |
| `Шахержон Тахержон` | одно поле `full_name` | текущие правила пропускают |
| `Shaherzhon Taherzhon` | обычный текст | текущие правила пропускают |
| `Ivan Petrov` | обычный текст | текущие правила пропускают |
| `Ivan` / `Petrov` | отдельные `first_name` / `last_name` | текущие правила пропускают |

Явно включённый NER дополняет эти правила модельными границами персон.
Работоспособность пути проверяется контролируемым recognizer и синтетическим
ONNX-графом на обоих алфавитах, коротких строках и за пределами первого окна.
Эти тесты не доказывают, что стандартные обученные веса узнают каждое имя.
Измерения готовой модели, загрузка весов и обучение в этой работе не выполнялись.

## Предлагаемое расширение

1. **Явные поля человека.** В отдельном расширении добавить политику полей
   `first_name`, `last_name`, `full_name`, `фио` без привязки к словарю русских
   имён и алфавиту. Типизированная запись человека позволяет скрыть всё значение.
   При этом определения схем, код и настройки (`first_name: String`) должны
   отличаться от реальных записей. Общие поля `name` и `title` сами по себе
   недостаточны: это могут быть товары, процессы и заголовки.
2. **Свободный текст.** Сочетать признаки имени и контекст с опциональным NER.
   Два слова с заглавных букв не должны автоматически считаться персоной.
   Для нового словаря/классификатора нужны отрицательные примеры товаров,
   организаций, топонимов, заголовков и обычных слов вроде «Роман готов».
3. **Отдельная оценка.** Проверить кириллицу, латиницу, транслитерацию и смешанную
   запись; имена с отчеством/без него, дефисы, апострофы, склонения и инициалы.
   Все записи одного вымышленного человека и варианты транслитерации должны
   попадать в одну часть train/test, чтобы разные написания не создавали утечку.
   Считать отдельно пропуски, частичные маски, ложные маски и блокировки атак.

Это план дальнейшего расширения, а не включённая по умолчанию новая политика.
Восстановление NER не расширяет автоматически область телефонных номеров:
правила по-прежнему предназначены для мобильных РФ. Возможные последующие
категории ПДн требуют собственного формата и проверки качества.
