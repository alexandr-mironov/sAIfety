# Конфигурация sAIfety

Настройки и поведение приложения. Обзор возможностей — в [README](../README.md).

## Файл конфигурации

sAIfety читает `saifety.json` из пользовательского каталога, **не** из проекта:
отравленный репозиторий не должен объявлять себя доверенным.

- Путь по умолчанию — `saifety/saifety.json` внутри пользовательского каталога
  конфигурации ОС: `~/.config` на Linux (либо `$XDG_CONFIG_HOME`),
  `~/Library/Application Support` на macOS, `%AppData%` на Windows.
  `$SAIFETY_CONFIG` переопределяет полный путь.
- Флаг `-config <path>` у команд `scan`, `proxy`, `hook`, `launch` переопределяет путь.

Пример:

```json
{
  "mcpServers": {
    "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"] }
  },
  "trustedSources": [],
  "classifier": "trained",
  "policy": "strict",
  "maxDecodeDepth": 3,
  "maxFileSize": 2097152,
  "claudeBinary": "claude"
}
```

### Поля

| Поле             | Значение по умолчанию | Описание |
|------------------|-----------------------|----------|
| `mcpServers`     | —                     | Апстрим MCP-серверы для прокси. Формат совместим с `.mcp.json`: `command`/`args`/`env` для stdio, `url`/`type` (`http`/`ws`/`sse`)/`headers` для удалённых. |
| `trustedSources` | пусто                 | Имена MCP-серверов, для которых прокси понижает уровень угроз при `policy: balanced`. При `strict` понижение отключено. |
| `classifier`     | `trained`             | `trained` — встроенная обученная модель без скачивания; `onnx` — английская DeBERTa, скачивается при первом использовании; `auto` — только уже скачанная ONNX-модель, иначе `lexical`; `lexical` — языковые эвристики. |
| `policy`         | `strict`              | `strict` (максимально строгий, по умолчанию) или `balanced`. |
| `maxDecodeDepth` | 3                     | Глубина рекурсивного декодирования вложенных кодировок. |
| `maxFileSize`    | 2 МБ                  | Файлы больше не сканируются при обходе репозитория. |
| `claudeBinary`   | `claude`              | Путь к бинарнику Claude для команды `launch`. |
| `redact`         | вкл.                  | Полное маскирование секретов и ПДн. Поля: `disabled`, `allowOpaque`, `keywords[]`, `allowlist[]`, `minEntropy`. Опциональный NER: `ner` (по умолчанию `false`), `noModel` (принудительное отключение), `nerLabels[]` (персоны по умолчанию). `keepIP` устарел. |

## Классификатор и модель

**Принцип.** Угроза — это не «в тексте есть команда», а **вредоносная инструкция,
нацеленная на агента** (перехват инструкций, jailbreak, директива на эксфильтрацию,
поддельное системное сообщение). Легитимные команды (`composer`, `rustup`,
`docker`, `npm install`, даже `curl | sh` из доки) — обычный контент проекта, не
атака. Это оценивает классификатор, обученный на своих сгенерированных вредных и
безвредных примерах (включая безвредные с командами). Детекторы команд учитывают
тип действия и контекст; наличие обычной команды установки не означает инъекцию.
Домен и проверка хэша авторитетом не считаются: на
доверенный домен можно залить вредоносный файл.

Модель `trained` включается в бинарник из Go-модуля
[prompt-injection-model](https://github.com/saifety-org/prompt-injection-model)
(логистическая регрессия на хэш-признаках char n-grams). Версия модуля закреплена
в `go.mod`; при запуске модели ничего не скачивается. Данные, обучение и оценка качества
находятся в [saifety-org/lab](https://github.com/saifety-org/lab).
Происхождение текущих весов:
[model.json](https://github.com/saifety-org/prompt-injection-model/blob/main/model.json).
`saifety version` показывает точную версию и SHA256 включённых весов.
Переобучение выполняется отдельно от сборки приложения; новый релиз модели
подключается явным обновлением зависимости и не заменяет веса автоматически.


По умолчанию используется встроенная модель `trained`. Трансформер
`protectai/deberta-v3-base-prompt-injection-v2` включается через `classifier: onnx`
(английская DeBERTa-v3, метки SAFE=0 / INJECTION=1).

- ONNX-модель (~738 МБ) не входит в репозиторий. Она скачивается в кэш
  при первом использовании `classifier: onnx` или через `saifety model pull`.
- Кэш: `~/.cache/saifety` (или `$XDG_CACHE_HOME/saifety`, или `$SAIFETY_CACHE`).
- Свой ONNX Runtime: `$SAIFETY_ORT_LIB`.
- Управление: `saifety model status | pull | path`.
- Сборка с трансформером требует тега `onnx` (`make build`). Сборка `make build-lite`
  даёт чистый Go без нативных зависимостей. Обе сборки по умолчанию используют `trained`;
  `lexical` выбирается конфигурацией или при откате недоступного ONNX.
- Если модель недоступна (не тот бинарник, нет сети), инструмент не падает, а
  откатывается на лексический классификатор с сообщением в stderr.

## Строгость (policy)

| Профиль    | MinConfidence | SureConfidence | Понижение для доверенных |
|------------|---------------|----------------|--------------------------|
| `strict`   | 0.25          | 0.55           | нет                      |
| `balanced` | 0.40          | 0.70           | да                       |

В прокси и хуках уровень угрозы определяет действие: base → предупреждение
(данные оборачиваются), medium → вырезание инструкций, critical → блокировка
источника. `scan` только выдаёт отчёт; файлы не изменяет. Категория `abort_bait`
(приманка, заставляющая проверяющего прекратить анализ) не удаляется и не
блокирует источник сама по себе: она обезвреживается на месте с пометкой, а скан
продолжается, чтобы поймать нагрузку за ней.

## Проверка MCP-ответов

В `tools/call` прокси анализирует декодированные JSON-ключи, строки и числа
всего результата: `content[].text`, `structuredContent` любой вложенности,
текст embedded resources, URI и описания resource links, annotations и
дополнительные поля. Для анализа сохраняются источник `server/tool`, тип
`tool_result` и настроенное доверие к серверу. Текст собирается в один документ;
это расширяет охват входных полей, но не гарантирует обнаружение каждой инъекции.

При `critical` весь ответ заменяется сообщением об ошибке, а источник попадает
в blocklist. При `base` или `medium`, связанном с инъекцией, весь ответ заменяется одним текстовым блоком
с предупреждением или очищенными данными; `isError: true` сообщает клиенту, что
исходный результат недоступен. Исходные `structuredContent`, resources и metadata
не пересылаются параллельно с очищенным текстом. Такой ответ не выдаётся за
успешный результат, соответствующий `outputSchema` инструмента.

Обычный ответ сохраняется целиком, включая расширения, числа и annotations.
Если найдены только ПДн или секреты, строковые значения полностью заменяются
на `[REDACTED:<тип>]`. Учитывается смысл явных полей: `first_name`,
`last_name`, `patronymic`, `phone` и их поддерживаемые варианты.
Контекст поля учитывается вместе с формой значения; схема `first_name: String`
не считается именем человека. E-mail, карты, адреса, IP, паспорта и даты
рождения находятся вне текущего профиля ПДн.
При маскировании числа безопасный JSON выдаётся текстом с `isError: true`;
ответ не объявляется соответствующим прежней числовой схеме. Обычные числа
сохраняют точность без преобразования через float64.

Секрет в JSON-ключе или поле протокола (`type`, URI, MIME type, annotations)
приводит к удержанию всего ответа без исходного содержимого: изменение таких
полей могло бы нарушить протокол или создать коллизию ключей. ПДн в
декодированном слое также удерживаются целиком. Если одновременно требуются
изменение ПДн и вырезание опасных инструкций с несовместимыми смещениями,
ответ удерживается; смещения классификатора не считаются границами ПДн.

Лимиты проверки: 32 МиБ JSON, 1 МиБ суммарного декодированного текста (включая
ключи и разделители), глубина JSON до 64 и до 65 536 значений. Превышение лимита,
невалидный результат, повторяющиеся JSON-ключи или прерванная проверка возвращают
ошибку без исходного содержимого и без постоянной блокировки источника.
`maxFileSize` эти лимиты не меняет. Встроенные `image.data`, `audio.data` и
`resource.blob` проверяются на корректность base64. При включённом
маскировании такие ответы по умолчанию удерживаются: их содержимое проверить
на ПДн нельзя, OCR в MCP-прокси не выполняется. Явная настройка
`redact.allowOpaque: true` разрешает передавать их без проверки ПДн.

Ошибки upstream передаются как нейтральная ошибка без исходных message/data.
В определениях инструментов удаляются содержащие ПДн default/examples;
description/title очищаются. Если ПДн входят в enum/const, имя свойства или
другое ограничение схемы, определение инструмента не выдаётся: удаление
ограничения могло бы расширить допустимые аргументы.

Это фильтр данных от MCP-серверов к агенту. Исходящие arguments передаются
сервису без переписывания: замена адресата или реквизитов изменила бы действие
инструмента. Настройки `allowlist`, `allowOpaque` и
`disabled` являются явными исключениями оператора. Фильтр не очищает
данные, уже находившиеся у агента, внешнего сервиса или в его собственных логах.

Поля результата описаны в [спецификации MCP](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#tool-result).

## Команды

```
saifety scan   [-config f] [-format text|json|sarif] [-v] [-ocr] [-deep] [-fail-on base|medium|critical] [path...]
saifety proxy  [-config f] [-state f]
saifety hook   [-config f] <session-start|pre-tool-use|post-tool-use>
saifety launch [-config f] [-force] [-dry-run] [dir] [-- claude-args]
saifety model  <pull|pull-pii|status|path>
saifety statistics [scan|proxy|hook] [-json] [-reset]          # счётчики обнаруженных угроз
saifety install   <claude-code|claude-desktop|cursor|windsurf|vscode|all> [-dry-run]
saifety uninstall <те же цели>                                   # восстановление из бэкапа
```

`-ocr` включает распознавание текста на растровых изображениях (нужен `tesseract` в PATH).

`-deep` сохранён для совместимости и сам по себе не включает NER. Его включает
только `redact.ner: true`, одинаково для обычного `scan`, прокси и хуков.
Классификатор инъекций выбирается полем `classifier`: обычный `scan` использует
`trained`, а для DeBERTa нужно указать `"classifier": "onnx"`.
Ход сканирования выводится в stderr.

## Результаты и разбор ложных срабатываний

Отчёт `scan` идёт в stdout, ход сканирования — в stderr (в файл/пайп не попадает).

**Текстовый формат (по умолчанию).** Для каждого файла с находками строка
`уровень действие путь`, ниже находки `уровень категория уверенность детектор:строка`:

```
base     warn     docs/install.md
    base     install              0.35 command:6
critical block    src/notes.txt
    critical instruction_override 0.98 classifier:1
```

Внизу итог: `N files scanned, K with findings, max level: ...`. Флаг `-v` добавляет
под каждой находкой фрагмент и пояснение.

**Машинные форматы.** `-format json` — все поля (source, category, level, confidence,
line, span, excerpt, message). `-format sarif` — SARIF 2.1.0 для CI и GitHub code scanning.

**Как читать уровни при проверке доверенного репозитория:**

- `base` — почти всегда шум на нормальном коде (`npm install`, упоминания в доке).
  Только предупреждает, ничего не режет.
- `medium` — стоит просмотреть (скрытый текст, закодированные блоки).
- `critical` — высокий оценённый риск; требует проверки, возможны ложные срабатывания.

**Рецепты для оценки шума:**

```sh
saifety scan -fail-on critical ./repo     # в коде возврата учитывать только critical
saifety scan -format json ./repo | \
  jq '[.verdicts[].findings[].category] | group_by(.) | map({(.[0]): length})'  # счёт по категориям
saifety statistics scan                    # сводка после скана: по уровням и категориям
```

Два важных момента при оценке ложных срабатываний:

- Обычный `scan` использует встроенную модель `trained`. Для DeBERTa выберите
  `classifier: onnx` и сборку `make build`; `-deep` не переключает классификатор.
  Протокол сравнения моделей находится в лаборатории.
- Режим по умолчанию `policy: strict` специально чувствительнее и даёт больше
  `base`-находок. Для «обычного» уровня шума поставь в конфиге `"policy": "balanced"`.

## Обезличивание (redact)

Маскирование секретов и персональных данных в том, что видит агент: применяется
к результатам инструментов в прокси и к выводу инструментов в хуках. В отчёте
`scan` они показываются как находки уровня base (`secret_material`, `pii`) — сам
скан файлы не переписывает.

- Секреты: ключи и токены AWS/GitHub/GitLab/Slack/Google/Stripe, приватные
  ключи, JWT, `api_key`, заголовки авторизации и пароли в URL.
- ПДн: русские ФИО и мобильные РФ с 11 цифрами, начинающиеся на `79`/`89`.
  Принимаются `+79…`, `79…`, `89…`, пробелы (включая неразрывные), скобки и тире.
  Десятизначные номера без кода, городские и иностранные номера не входят в профиль.
  Из длинного ID не извлекается одиннадцатизначный фрагмент.
- Для ФИО используются небольшой словарь имён, признаки фамилии и отчества,
  распространённые склонения, инициалы, дефисы, порядок частей и контекст поля.
  Заглавные буквы сами по себе не являются признаком имени. Редкие имена,
  неоднозначные слова и необычные формы могут давать пропуски и ложные срабатывания.
- Голый 11-значный номер в `order_id`, `order_number`, `order_no` или после
  явной подписи «Номер заказа»/`Order` сохраняется как заказ. Это осознанное
  контекстное исключение: телефон, ошибочно записанный в таком поле, может пройти.
  Оно не отключает проверку секретов, ФИО и оформленных телефонов в этом значении
  и не влияет на соседние контактные поля. Префиксы конкретных компаний не зашиты.
- E-mail, карты, паспорта, СНИЛС, ИНН, адреса, даты рождения, IP и латинские имена
  больше не маскируются автоматически как ПДн. Это сужение профиля, а не гарантия
  полного обезличивания произвольных персональных данных.
- `keywords[]` добавляет строки для маскирования; `allowlist[]` задаёт исключения
  оператора; `minEntropy` включает поиск высокоэнтропийных секретов.
- Найденный фрагмент целиком заменяется на `[REDACTED:<тип>]`.
  Если обнаружение потребовало Unicode-нормализации, скрывается всё строковое
  значение, поскольку смещения нормализованного текста нельзя применить к исходному.

### Опциональный NER

По умолчанию действуют только приведённые выше правила. Для явного включения:

```json
{"redact": {"ner": true}}
```

Нужна сборка с `-tags onnx` и заранее подготовленные файлы модели. Отдельная
команда `saifety model pull-pii` загружает PII-бандл: ONNX-конверсию
`Xenova/bert-base-multilingual-cased-ner-hrl`, tokenizer/config и runtime.
Обычная `saifety model pull` продолжает загружать только модель инъекций.
`proxy`, `hook` и `scan` веса не скачивают. `SAIFETY_CACHE` задаёт каталог кэша,
`SAIFETY_ORT_LIB` позволяет указать уже установленный native runtime.

- Даже валидный кэш не включает NER автоматически. `noModel: false`,
  `nerLabels` и `-deep` не заменяют `ner: true`.
- `noModel: true` имеет приоритет и оставляет только правила. `disabled: true`
  по-прежнему отключает маскирование результатов целиком.
- По умолчанию NER добавляет только персоны (`PER` и поддерживаемые алиасы),
  не организации, местоположения или даты. `nerLabels: ["PER", "LOC"]`
  явно расширяет модельные категории. Наличие метки в настройке не добавляет
  её модели: у стандартного бандла есть PER/ORG/LOC, а DATE нет.
- Включённый NER дополняет правила, в том числе в кириллице и латинице.
  Его качество на конкретных именах требует отдельного измерения; наличие
  технического пути и успешный тестовый граф этого не подтверждают.
- Модель проверяет текст окнами до 512 токенов с перекрытием, максимум 32 окна.
  Неполная проверка, ошибка инициализации/инференса или отсутствие файлов
  не превращаются в молчаливый переход к правилам: MCP удерживает результат,
  hooks скрывают непроверенный вывод, `scan` сообщает об ошибке инициализации.
- Один recognizer разделяется между сканированием и маскированием в процессе
  прокси/хука; принадлежащая ему ONNX-сессия закрывается после завершения.

`keepIP` остаётся неактивной совместимой настройкой: IP вне основного профиля.
Классификатор инъекций независимо выбирается полем `classifier`.
[Проверка опционального пути](optional-ner-evaluation.md),
[предыдущая проверка основного режима](russian-pii-evaluation.md) и
[варианты работы с именами в разных письменностях](name-scripts.md).

## Целостность MCP-инструментов

Прокси при выдаче `tools/list` проверяет каждый инструмент и добавляет в описание
предупреждения о целостности. Отдельная политика ПДн может удержать определение,
если его нельзя очистить без изменения ограничений схемы:

- **Rug-pull** — определение инструмента изменилось с момента первого показа
  (пиннинг хэшей в `~/.local/state/saifety/toolpins.json`, `$SAIFETY_PINS`).
- **Cross-origin / shadowing** — описание ссылается на другие серверы/инструменты
  или пытается подменить их использование.
- **Коллизия имён** — один и тот же инструмент отдают несколько серверов.

## Запуск Claude под защитой (launch и хуки)

`saifety launch [dir]` — сценарий «просканировать и запустить». Он сканирует папку
(по умолчанию текущую), и если нет критичных угроз, запускает Claude уже под защитой.
При критичной находке запуск отменяется (переопределяется флагом `-force`). Флаг
`-dry-run` показывает, что будет сгенерировано, ничего не запуская. Путь к бинарнику
Claude берётся из поля `claudeBinary`.

Что `launch` настраивает во временном профиле Claude Code (проектные файлы не
меняются):

- **Отключает штатную загрузку `CLAUDE.md`** (`instructionFiles: managed-only`) и
  подаёт проверенные инструкции через хук `SessionStart` — так отравленный
  `CLAUDE.md` не попадёт в контекст напрямую.
- **`claudeMdExcludes`** закрывает ленивую загрузку вложенных `CLAUDE.md`.
- **Единственный MCP-сервер — `saifety`** (`--strict-mcp-config`): агент ходит в
  апстримы только через прокси.
- **Хуки** `PreToolUse` (запрет заблокированных источников) и `PostToolUse`
  (маскирование и обезвреживание вывода инструментов).

Те же хуки можно подключить к существующей сессии Claude Code вручную через команду
`saifety hook <session-start|pre-tool-use|post-tool-use>` (адаптер читает JSON хука
из stdin и пишет решение в stdout). Обычно это делает `launch` автоматически.

Альтернатива без прокси — шелл-цепочка `saifety scan -fail-on critical && claude`.

## Статистика

`saifety statistics` показывает накопленные счётчики обнаруженных угроз: сколько
документов просканировано, сколько находок, разбивка по уровням и категориям,
действия (block/sanitize/warn) и топ источников. Счётчики разделены по областям:
`scan` (разовое сканирование), `proxy` и `hook` (рантайм) — каждая в своём файле
`~/.local/state/saifety/stats-<область>.json` (каталог переопределяется
`$SAIFETY_STATS_DIR`). Без аргумента показываются все области; можно указать одну:
`saifety statistics proxy`. Флаги: `-json` для машинного вывода, `-reset` для
сброса (всех или указанной области).

## Блок-лист

Критичные источники записываются в `~/.local/state/saifety/blocklist.json`
(или `$SAIFETY_STATE`) и общие для прокси и хуков. Разблокировка — вручную, правкой
или удалением файла. Уже запущенные процессы перечитывают состояние перед
проверкой доступа: блокировка из hook действует в proxy, а ручное удаление
записи не восстанавливается из старого снимка другого процесса.

Чтение и обновление защищены mutex внутри процесса и системной файловой
блокировкой между процессами. Обновление перечитывает актуальный JSON под
блокировкой, добавляет записи и заменяет файл закрытым, синхронизированным
временным файлом из того же каталога. На Unix синхронизируется также каталог;
на Windows согласованность чтения обеспечивается общей файловой блокировкой.
Новый файл имеет права `0600`; формат `entries` совместим с прежним. Старое
служебное поле `Path` игнорируется: путь задаётся только конфигурацией.

Ожидание файловой блокировки ограничено двумя секундами. При повреждённом
JSON, ошибке чтения или блокировки доступ не разрешается: `PreToolUse` выдаёт
явный `deny`, MCP возвращает ошибку и пишет причину в stderr. Ошибочная запись
не затирает прежний файл; не сохранённая блокировка остаётся в текущем процессе
и повторно сохраняется при следующем успешном `Block`. Ошибка сохранения
показывается в диагностике; она не означает, что блокировка нигде не действует.

Для ручной правки остановите процессы записи, исправьте или удалите JSON и
запустите их снова, особенно после ошибок сохранения. Служебный файл
`blocklist.json.lock` удалять нельзя: его имя и inode объединяют участников
блокировки. Блокировка снимается ОС при завершении процесса, наличие `.lock`
не означает зависшую блокировку. Все процессы должны использовать новую
версию; старые бинарники не соблюдают этот протокол. Состояние рассчитано на
локальную файловую систему с поддержкой системных блокировок.

## Перехват конфигурации Claude

`saifety install` переносит все MCP-серверы из конфига клиента в `saifety.json` и
подставляет вместо них единственный сервер `saifety`, который проксирует их с
проверкой. Прокси поддерживает все транспорты MCP (stdio, http, ws, sse), поэтому
переносятся и локальные, и удалённые серверы. Поддержанные клиенты и пути:

| Клиент | Файл | Ключ |
|---|---|---|
| `claude-code` | `~/.claude.json` | `mcpServers` |
| `claude-desktop` | `~/Library/Application Support/Claude/claude_desktop_config.json` | `mcpServers` |
| `cursor` | `~/.cursor/mcp.json` | `mcpServers` |
| `windsurf` | `~/.codeium/windsurf/mcp_config.json` | `mcpServers` |
| `vscode` | `~/Library/Application Support/Code/User/mcp.json` | `servers` |

Перед изменением создаётся резервная копия; `saifety uninstall` восстанавливает её.
Клиент применяет изменения после перезапуска. Всегда сначала запускай с `-dry-run`.

## Experimental contextual model

Optional `experimentalContext` enables advisory Go/ONNX inference alongside the
existing classifier. It is off by default and cannot change blocking decisions.
See [contextual inference](contextual-inference.md) for local artifact pins, the
JSON API, explicit operator task in MCP/hooks, segmentation, limits and errors.
